# UI library migration

The current Orbit interface now uses shadcn/ui (Radix) and Tailwind CSS v4.
The original component migration preserved Orbit styling. The approved DESIGN.md
follow-up now applies the Indigo Panel System: locally hosted Geist, neutral pill
actions, hairline containers and indigo panels. Existing theme names, translated
copy, controlled fields and API calls remain in place.

- `src/components/ui/`: primitives generated by the official shadcn CLI, then adapted to the current design. Native selects deliberately keep their native element and layout; textareas retain `rows` sizing.
- `src/styles/tokens.css`: DESIGN.md light/dark values, legacy compatibility aliases and shadcn semantic mappings. `src/index.css` imports it and retains the existing page/editor styles.
- `src/lib/utils.ts`: `cn()` combines `clsx` and `tailwind-merge`.
- Routes and shared components use the new primitives or Tailwind utilities. Button-like navigation uses `buttonVariants()` without changing link semantics.
- Account dropdown and catalog/archive tabs use Radix keyboard handling. Existing native validation, request handlers, translations and session logic remain in place.
- `components.json` and TypeScript/Vite aliases support future `npx shadcn@latest add <component>` commands.
- DaisyUI is removed from dependencies, CSS plugins and source classes.

## Checks

From `client/`:

```sh
npm test
npm run test:e2e
npm run lint
npm run build
npm run check:boundary
```

Vitest covers native form validation/submission, disabled controls, link semantics,
menu dismissal/focus return, controlled tabs, theme persistence and EN/DE archive
filtering. Playwright checks EN/DE navigation and six public routes at 360 px,
theme persistence, desktop field dimensions, bounded long textareas and a real
customer demo login. It uses the existing API proxy and never starts/seeds/resets
the backend. Test artifacts and authenticated state directories are ignored by Git.

The fresh-session customer demo login currently returns HTTP 401. This test remains
failing rather than masking the API response. See
[FE-20261110-demo-customer-login](../docs/handoffs/tickets/FE-20261110-demo-customer-login.md).
Admin read-only workflows are now tested with the README-documented `admin@orbit-it.de`
account (overridable through `E2E_ADMIN_EMAIL` / `E2E_ADMIN_PASSWORD`). The displayed
customer demo still requires confirmation. Technician read-only workflows are
covered separately below.

On Windows, `check:boundary` requires Git Bash on the terminal PATH. The check itself
is unchanged. No backend, API contract, generated route tree, or Agent.md edits were
made as part of this migration.

## Admin visual migration

`AdminDashboardShell.tsx` reuses the existing dashboard layout, with styles scoped
to `.admin-dashboard`. Overview, requests/detail, orders, tickets, catalog, CMS,
users, messages, contact inbox and activity now follow DESIGN.md. Customer and
technician style scopes are unchanged.

`e2e/admin-design.spec.ts` checks these 11 routes in EN/DE, light/dark, 360/1440 px,
search clearing, catalog tabs and opening product/CMS/conversation forms. It logs
in through the real UI and API and does not save, send, assign, change roles,
deactivate or delete. Business mutation requests after login are asserted absent.

The first standalone Admin EN/DE matrix passed. A subsequent full-suite run hit
the API rate limit (HTTP 429), affecting later Admin and public catalog checks.
The Admin test now uses existing router links and checks viewport/theme variants
on each mounted page, avoiding repeated full reloads and provider requests.
Rerun after the server-provided Retry-After interval; do not disable the limiter.

The subsequent Admin EN/DE and public design EN/DE checks passed with the reduced
request strategy during the Technician migration run.

## Technician visual migration

`TechnicianDashboardShell.tsx` reuses `DashboardShell`, with styles scoped to
`.technician-dashboard`. Overview, assigned requests, tickets/detail,
appointments and reports now follow DESIGN.md. Shared messages/account pages
receive this scope only for the TECHNICIAN role. The scope includes Geist,
neutral pill actions, consistent form/card spacing, an indigo overview panel,
readable sky-panel metadata and wrapping German account actions on mobile.

`e2e/technician-design.spec.ts` passed in EN and DE. It checks eight routes in
light/dark at 360/1440 px, search clearing, report request preselection, native
required fields, local attachment selection and opening a new conversation.
It uses the real README technician login, overridable through `E2E_TECH_EMAIL`
and `E2E_TECH_PASSWORD`. It never submits reports, updates statuses, sends
messages or changes profile data; post-login API mutations are asserted absent.
Report submission and file upload to the server were not exercised.

Source comparison confirmed unchanged API calls, query/state setup, event
handlers, FormData fields, native validation and navigation attributes across
the Technician routes and shared messages/account pages. Ten unit tests, lint,
production build and the frontend boundary check passed. No backend changes
were needed for this role migration.

The final shared-interface regression run passed three checks (EN/DE mobile
navigation/forms/theme and desktop dimensions). The existing customer demo
login check still fails with HTTP 401, as recorded in the ticket above. Combined
with the Admin/public design and Technician runs, nine E2E checks passed and
that one known customer-authentication check failed; this was verified in
separate runs rather than a single all-green suite.

## Animated workspace sidebar

The user-requested [Be UI Animated Sidebar](https://beui.dev/components/motion/animated-sidebar)
now replaces the shared dashboard navigation for Customer, Admin and Technician.
Adapted upstream source lives in `src/components/beui/`; `DashboardSidebar.tsx`
composes it with existing role navigation, translations and the TanStack router.
The frontend adds Motion, which is required by this component.

Desktop navigation morphs into an icon rail and remembers the expanded state in
browser-local storage (no authentication data). Real anchor hrefs, modified
clicks, nested-route active states and all role-specific destinations remain.
The separate mobile surface uses a native modal dialog with the Be UI motion,
so the browser provides top-layer placement and outside inertness. Escape,
explicit close, backdrop dismissal and navigation close the drawer; focus returns
to its trigger. Reduced motion disables the slide/morph. EN/DE labels and sizes
use existing translations and design tokens. No API or permission changes.

`e2e/sidebar.spec.ts` covers the three roles in both languages, expanded/collapsed
navigation, persistence across routes, keyboard activation, active links, mobile
dialog focus and Escape, navigation dismissal and 360 px overflow.
`E2E_BROWSER_CHANNEL=chrome` selects installed Chrome when the bundled Playwright
Chromium cannot launch; leaving it unset preserves the original test default.

`e2e/sidebar-component.spec.ts` uses a test-only Vite HTML entry and memory
router with the real role navigation and sidebar. No API requests or auth mocks
are used, and the fixture is not a production build entry. All six role/language
cases passed after the final fixes, including light/dark, reduced motion, rail
dimensions, shortcuts outside editable fields, five mobile open/close cycles,
native modality, backdrop/Escape dismissal, focus return and SPA navigation.
Native modal focus can enter browser chrome; the test checks that page controls
remain unreachable rather than adding a custom focus trap.

The full live-API suite completed with 11 passes and five failures before the
last fixes: four logins were blocked by HTTP 429 after repeated runs, and one
mobile opening race was corrected by synchronizing native dialog opening in a
layout effect. The corrected behavior is covered by the API-free matrix; the
live suite still needs a fresh run after the login limiter expires. The existing
customer demo-card credential issue is unchanged. No security control was
disabled, and no backend changes or business mutations were made.
