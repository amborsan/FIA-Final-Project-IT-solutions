# Orbit IT Solutions — Frontend

React 19 + TypeScript + TanStack Router + TanStack Query + Tailwind CSS 4 +
DaisyUI 5.

## Quick start

```bash
cd client
npm install
npm run dev
```

Open `http://localhost:5173`. The Vite dev server proxies `/api` to the Express
server on port 3000. Start the backend first.

Production build:

```bash
npm run build
```

The backend serves `client/dist` automatically when it exists.

## Routing conventions

TanStack Router generates `routeTree.gen.ts` from the filenames. Add a route by
creating `src/routes/my-page.tsx`:

```tsx
import { createFileRoute } from "@tanstack/react-router";

export const Route = createFileRoute("/my-page")({
  component: MyPage,
});

function MyPage() {
  return <div>Hello</div>;
}
```

Do not edit `routeTree.gen.ts` by hand. It is regenerated by `npm run dev` and
`npm run build`.

## API client

Use `src/lib/api.ts`:

```ts
import { api } from "../lib/api";

const data = await api<{ services: Service[] }>("/services");

await api("/requests/public", {
  method: "POST",
  body: { title: "New network", /* ... */ },
});
```

The client automatically:

- sends cookies (`credentials: "include"`),
- fetches and attaches the CSRF token for POST/PATCH/DELETE,
- throws `ApiError` with the server's message,
- supports `FormData` for uploads.

Types for the API live in `src/lib/types.ts`. Keep them in sync with the backend
contract; do not invent extra fields.

## Auth and roles

`AuthContext` loads `/auth/me` on start. Wrap protected pages with
`<RequireRole roles={["CUSTOMER"]}>`. The server still enforces permissions.

Dashboard layouts live in `portal.tsx`, `technician.tsx`, `admin.tsx`; each
child page renders `DashboardShell` with a translated nav from
`components/nav.ts`.

## Bilingual UI (EN/DE)

- English is the primary language, German is secondary.
- All labels go through `useI18n().t("key")`.
- Both dictionaries are in `src/i18n/translations.ts`. Add the key to **both**
  `en` and `de` objects.
- API records contain both `nameEn/nameDe`, `titleEn/titleDe`, etc. Use
  `pick(record.nameEn, record.nameDe)`.
- Dates/currency use `formatDate`, `formatDateTime`, `formatMoney`.
- The selected language is stored in `localStorage` (`orbit_language`).

Never hardcode user-facing English or German text in a component.

## Design system

- DaisyUI theme `orbit` in `src/index.css` (professional blue/teal).
- Reusable classes: `container-page`, `section-space`, `eyebrow`, `card-hover`,
  `prose-content`, `legal-copy`.
- Shared components: `Header`, `Footer`, `ProductCard`, `ServiceCard`,
  `StatusBadge`, `PageLoader`, `ErrorState`, `EmptyState`, `RichText`.
- Icons come from `lucide-react`; service icons are mapped in `ServiceIcon.tsx`.

## Legal pages

The header/footer link to `/legal/imprint`, `/legal/privacy`, `/legal/terms`,
`/legal/withdrawal`, `/legal/cookies`. They are bilingual and use
`LegalShell`. Cookie settings can be reopened from the footer or any legal page.

When changing forms that collect personal data, keep the privacy checkbox
required and mention the legal links. The server stores consent timestamps.

## Important rules for frontend agents

The binding contract is [`Agent.md`](./Agent.md), with per-developer prompts in
[`agents/`](./agents/). Summary:

1. **Never edit anything in `../server`**, including the Prisma schema, routes,
   migrations, seed, tests, `.env` or `package.json`. The backend is owned by the
   backend developer.
2. If you need a new endpoint, field, permission, validation or database change,
   create a ticket in `../docs/handoffs/tickets/` from the template, link it in
   `../docs/handoffs/frontend-to-backend.md`, and tell the **backend developer
   only**. Never implement it yourself or fake it in production code.
3. Do not edit `routeTree.gen.ts`.
4. Add every new text key to both languages.
5. Run `npm run lint`, `npm run build` and `npm run check:boundary` before
   finishing.
6. Keep the existing design language and reusable components; this project
   should stay understandable for junior developers.
